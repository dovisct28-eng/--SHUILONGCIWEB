## 三、本次目标

制作一个独立、可在 localhost 打开的 A01 低保真交互原型，验证以下连续体验：

**空间穿越 → 建筑旋转生长 → 建筑左移 → 文字浮现 → 稳定阅读**

重点解决：

1. 空间穿越与建筑初现能否自然衔接。
2. 现有模型是否能根据滚动进度旋转、生长和反向还原。
3. 建筑从中央移到左侧时，是否完整、连续且构图稳定。
4. 最终文字是否清晰可读。
5. 阅读区间是否足以缓冲动画结束与下一阶段的衔接。

本次不追求最终材质、灯光和文化视觉包装。

## 四、开发范围与边界

- 先识别项目实际结构，再新建独立的模块 A 原型目录。
- 复用现有建筑模型和适用的展示逻辑。
- 保留已有模型预览及二维生长预览。
- 不修改模块 B 的核心代码、数据和交互。
- 不开发 A02—A06 的正式内容。
- A01 末尾只设置简单的 A02 衔接占位，用于检查阅读区间结束后的过渡。
- 不修改或覆盖壁画母版素材。
- 不引入非必要的在线服务或依赖。

## 五、交互规格

### 1. 统一滚动进度

动画状态由页面滚动位置决定：

- 向下滚动：推进。
- 向上滚动：还原。
- 停止滚动：保持当前状态。
- 在同一窗口尺寸下，同一进度应得到相同画面。
- 快速跨越多个阶段后，仍应得到正确状态。

旋转与生长不得依赖独立运行的计时器，也不能通过触发一次自动播放代替滚动控制。

### 2. 阶段划分

以下比例用于首版验证，可以根据实际体验调整并记录原因：

| 动画进度 | 阶段 | 主要表现 |
|---|---|---|
| 0%—20% | 空间穿越 | 分层推进、缩放和遮罩，入口逐渐离场 |
| 20%—65% | 建筑旋转生长 | 建筑中央出现，底座、主体、屋顶逐渐显现，伴随缓慢旋转 |
| 65%—82% | 建筑左移 | 停止旋转，连续调整位置与展示尺寸 |
| 82%—100% | 文字浮现 | 标题、介绍和探索提示依次出现 |
| 动画结束之后 | 独立阅读区间 | 保持最终 Hero 不变，滚过该区间后衔接 A02 |

阅读区间单独占用滚动距离，不挤占四阶段比例。

### 3. 阅读区间

- 建筑停止旋转、生长和移动。
- 文字完整显示，构图保持稳定。
- 不设置自动倒计时，不强制等待新的滚轮手势。
- 用户继续滚动，走完该区间后进入 A02 衔接占位。
- 反向滚动先回到稳定 Hero，再反向还原前面的动画。

区间长度是本次需要调试的参数，不预设固定秒数。

## 六、五个关键画面的实现要求

| 画面 | 对应状态 | 本次重点 |
|---|---|---|
| 01 空间入口 | 0% | 明确纵深、视觉中心和向下滚动提示 |
| 02 建筑初现 | 约 20% | 入口残留与建筑初现保持连续，避免整屏闪切 |
| 03 旋转生长 | 约 55% | 检查建筑体量、角度、显现顺序和遮挡 |
| 04 左移与文字进入 | 约 85% | 建筑左移完成，文字开始渐显 |
| 05 最终 Hero | 100%及阅读区间 | 左侧完整建筑、右侧文字、底部探索提示 |

Figma 中的灰色区域是构图范围，不是建筑几何形状。接入模型后，应根据真实投影调整大小和留白，不能为了填满占位区域而拉伸建筑。

## 九、建议实施顺序

1. **检查结构与复用条件**：确认入口、模型加载方式、现有动画逻辑、依赖及本地启动方式。
2. **验证模型进度控制**：先完成旋转、生长的前进、暂停和反向还原，检查阶段边界。
3. **搭建完整滚动流程**：接入二维穿越、建筑左移、文字显现及阅读区间。
4. **对照五帧调整布局**：固定关键进度检查建筑范围、文字位置和过渡连续性。
5. **完成浏览器验证与提交**：修复发现的问题，记录验证结果和仍待确认的参数。

## 十、测试与验收

至少验证：

- 五个关键进度与分镜意图一致。
- 各阶段边界正向、反向经过时无明显闪切。
- 停滚后模型及文字状态稳定。
- 快速滚动、拖动滚动条后状态正确。
- 刷新或恢复到中途位置时，不出现错误初始状态。
- 调整窗口尺寸后，进度和布局重新计算正确。
- 建筑左移和最终停留时不被裁切。
- A01 全程没有壁画编号或定位标记。
- 阅读区间内画面保持稳定，结束后才能进入衔接占位。
- localhost 下模型和必要资源正常加载，无控制台运行错误。

桌面布局至少检查：

- 1440 × 900
- 1440 × 1024
- 1366 × 768
- 1920 × 1080

为进度映射和阶段边界编写有实际价值的测试；运行适用的构建检查和浏览器验证。没有构建步骤时，应明确说明。性能结论记录实际测试环境，不凭感受宣称达标。
