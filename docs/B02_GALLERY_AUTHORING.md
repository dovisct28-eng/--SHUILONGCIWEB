## 作者新增人物：实际操作

1. 在 `Mural-Exhibition/public/assets/` 新建编号文件夹，例如 `11_待录入名称`。每组人物一个文件夹；编号不得与已有 ID 重复。名称由作者填写，系统不会推断身份。
2. 放入 `org.png`，也支持 `org.webp`、`org.jpg`、`org.jpeg`。其余素材可稍后补充。无需改 HTML、热点数组或人物菜单。
3. 在 PowerShell 打开本项目，执行下列命令（3002 可与普通观众的 3000 服务并存）：

   ```powershell
   Set-Location 'D:\YJS\出兵入将-PC端页面\Mural-Exhibition'
   $env:PORT = '3002'
   npm run start:admin
   ```

4. 浏览器打开 `http://localhost:3002/index.html`，点击「图鉴探索」，再点击右下「标注管理」。服务器需要一直运行；Ctrl+C 关闭。
5. 点击「重新扫描素材」。新人物显示「待标注」，普通全景中没有其热点。可搜索名称或 ID。
6. 先选人物后点击对应壁画，或先点击壁画再选人物，两种顺序均支持。临时圆点与 X/Y 百分比只是预览，不立即写文件。
7. 可拖动、滚轮缩放后继续标注，点击新位置修正；「取消」恢复保存前的坐标。
8. 点击「保存」，等待「坐标保存成功」。系统生成或更新该文件夹的 `meta.json`，热点立即生效。刷新页面再检查，点击热点应进入该人物。
9. 后续放入 `line.png`、`color.png`、`video.mp4`、`info.txt` 或 `info.md`，重新扫描即可识别。观众从 B01 重新进入图鉴也会扫描最新资源。
10. 修改坐标：选已标注人物 → 点击新位置 → 保存。取消绑定：选人物 →「取消绑定」预览 →「保存」确认。只清空 position，不删除任何素材。

保存失败会恢复前端原坐标，服务端原子写入失败保留原文件；配置若被外部修改，返回冲突，重新扫描再编辑。不要在多个窗口同时修改同一人物。测试人物已清理，正式目录仍只有原 8 组。

普通观众启动：清除本地 `PORT` 环境设置（若已设置）后在 Mural-Exhibition 执行 `npm start`，默认 `http://localhost:3000/index.html`。普通启动默认关闭管理入口和写入能力。不要把管理模式作为普通展陈运行方式。依赖缺失时先 `npm install`；不需要数据库或云服务。

## meta.json 最终规范

```json
{
  "id": "11",
  "name": "作者填写的正式名称",
  "order": 11,
  "category": "",
  "position": { "x": null, "y": null },
  "sources": []
}
```

- `id`：稳定且唯一的字符串，1–64 个 ASCII 字母、数字、下划线或连字符。已有 ID 为 01–07、10。不能用路径作 ID。
- `name`：非空正式显示名称，独立于文件夹名称。保存后改文件夹名不改变 name/id。
- `order`：有限数值，升序排列；相同顺序按 ID 排列。
- `category`：字符串，可空。系统不自动推断分类或人物身份。
- `position`：两项都为 null 表示未标注；完成后两项均为 0–100 的有限数值，基于完整全景，最多保留四位小数。不会把未标注放到 (0,0)。
- `sources`：资料来源数组，可空。现有档案原文继续保留；本轮没有重新核验其全部研究论断。正式名称沿用已有绑定，不构成新身份考证。

没有 meta 的编号文件夹可扫描：首次使用编号和文件夹后缀作为临时 ID/name，position 为 null；保存位置时自动生成上述元数据。建议先创建 meta，填写正式名称和来源。损坏配置或重复 ID 会被跳过并在管理扫描结果中显示具体诊断，不静默改写。

统一检测规则（小写文件名）：图片 **webp → png → jpg → jpeg**；档案 **info.md → info.txt**；动画只检测 `video.mp4`。多版本时按上述优先级，前端不会猜测文件路径。Markdown 档案当前按纯文本显示，避免执行 HTML；B03 后续可以在同一资源结构上扩展排版。只有原图也可进入详情；线稿/色稿缺失时按钮禁用；无视频不请求；无档案显示「人物档案待补充」；原图未就绪明确提示，不设置破损图片 src。

## 桌面图鉴详情的独立媒体展示（2026-10-08）

人物详情保留左侧显示容器和现有两栏位置，取消固定矩形边框、底板及画框装饰。每张原图、线稿、色稿以完整作者画板独立居中显示，使用自然宽高比、`object-fit: contain` 和最大宽高约束；小画板不强制放大。PNG 的透明边距属于画板内容，照原样保留，不自动裁剪、移动、配准或按人物 ID 设置缩放。

三张静态图与视频由局部 `commitGalleryMedia(org|line|color|video|none)` 管理 `hidden`，同一时刻最多一个媒体可见，不使用 opacity 叠层或交叉淡化。图像在不可见状态加载并解码，校验 `layerVersion`、`detailVersion` 和请求取消状态后才提交；加载中保留上一张有效图像及其选中按钮，目标按钮使用 `aria-busy` 标识等待。加载失败保留当前图像，提供“重试图像”；切换人物清空旧图源、就绪标记和尺寸诊断。

三种素材不要求相同像素尺寸、宽高比、透明边距或人物位置。尺寸差异仅写入 `#image-wrapper` 的 `data-dimensions` / `data-dimension-match` 内部诊断，不阻止观看，也不提示“无法保证配准”。左下说明为“原图 · 线稿 · 色稿”，有加载/失败状态时沿用优先显示状态文字的规则。

数字色稿先显示成功解码的静态图。有 `video.mp4` 时，视频开始播放并具备画面数据后独占展示；自然结束后恢复静态色稿。视频文件缺失、格式不支持或播放被拒绝时自动回退静态色稿并提示；切换图层、人物或离开详情时暂停、清空视频源、移除旧回调，版本校验阻止旧播放结果重新显示。

验证：`node --test Mural-Exhibition/b02.test.cjs`、`node Mural-Exhibition/b02-browser-check.cjs`。后者包含 `b02-media-browser-check.cjs` 的逐帧互斥、延迟请求/解码、错误重试、视频及四视口检查；该媒体脚本也可单独运行。比例/透明边距素材只生成在操作系统临时目录，通过测试浏览器路由提供，不进入正式人物目录。详见 [本次验收记录](validation/b02-media-switch-2026-10-08/README.md)。

## 接口与本地管理约束

- `GET /api/scan-assets`：`{success, adminEnabled, data, diagnostics}`。每个人物包含元数据、folderName、resources（org/line/color/video/info）、annotated、ready、revision。继续返回 orgPath/linePath/colorPath/infoPath 等兼容别名，移动页沿用原接口。
- `GET /api/gallery-admin/characters`：仅管理开启且本机有效 Host/同源请求允许，返回同一数据和进程内写入令牌。
- `POST /api/gallery-admin/position`：JSON `{id,position,revision}`；需准确 Origin 与 `X-Gallery-Token`。位置无效 400、人物不存在/配置损坏 404、配置冲突 409、管理关闭/来源校验失败 403、磁盘失败 500。
- 人物文件夹由服务端扫描后的稳定 ID 查找，客户端不能指定任意写入路径。不扫描符号链接/目录联接，不允许 meta 符号链接。仅临时文件写入后 rename 替换 `meta.json`，失败清理临时文件。其他元数据字段保留。
- Host 只接受 localhost/127.0.0.1/[::1]，请求远端地址必须 loopback；跨站 Origin、null Origin、跨站 Fetch Metadata 被拒绝。普通服务保留既有网络监听行为，写接口仍限制本机；独立管理启动器只监听 localhost。URL 参数和隐藏按钮不能开启服务端权限。
