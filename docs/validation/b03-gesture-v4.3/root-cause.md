## 修改识别逻辑前的代码证据

- 人体身份以双肩中心和肩宽匹配，不依赖手腕或手臂；缺少髋部仍使用同一个上半身锚点。人体匹配竞争、中心越界或过期 Pose 会暂停分配，持续 1000ms 未观测才释放。日志中的 visitor-4 不能证明同一人曾被错误换号。
- `resolveHandSide()` 要求短期轨迹与最近肩膀侧别一致；手腕缺失且单手自然穿过肩膀中线时，即使上一帧轨迹连续，也可被拒绝为 AMBIGUOUS_SIDE。
- `assign()` 每帧先做全局手腕/肩膀匹配；任意检测的 AMBIGUOUS_SIDE、HAND_JUMP 或 AMBIGUOUS_PERSON 都清空全部分配。它不知道 HandOwnership 已锁定哪只手，因此非控制手的侧别问题也可取消控制手的有效观测。
- Hands 与 Pose 异步运行；真实记录 Hands 24.89 FPS、Pose 9.24 FPS，Pose 延迟 P95 139.2ms。仍在新鲜预算内的 Pose 手腕位置也可能落后于当前手掌；每帧重新侧别匹配不能视作连续身份的唯一证据。
- 控制手身份已有 650ms 保留窗口，200ms 后需要 250ms 恢复；上游清空分配会被下游解释为不可用，持续拒绝最终释放。此机制合理，不能通过一律放大超时掩盖上游错误。
- 现有固定映射 x=.2–.8；按钮中心对应镜像掌点 x=.278/.722，中心到单侧需移动 .222 画面宽。视觉目标位置由实际 DOM 测量，预览 CSS 镜像不参与推理，掌点在 Tracker 只镜像一次。
- 驻留允许同手安全间断最多 200ms 保留旧进度；本任务要求恢复后重新开始，需改为任何无效观测立即清零，仍保留动作后新鲜稳定移出全部按钮 250ms 的释放条件。

## 计划中的复现和修复边界

先用连续轨迹复现跨中线和异步腕点问题，再修复。首次获取继续使用严格人体/手腕归属；锁定后使用同操作者同语义手的有限历史轨迹、人体平移/尺度和当前新鲜检测确认。多人竞争、交叉、重复候选、明显跳变、旧数据仍暂停；不依据数组顺序接管。不改 200/650/250ms 时序及 1000ms 驻留。任何暂停取消进度，离开按钮的新鲜稳定证据才解锁。收窄横向输入范围，保留按钮与预览布局。增加仅 debug 开启、有容量上限且量化的派生诊断；不导出图像或关键点序列。

## 已执行复现与最终修复

修改前，两项专项复现均失败（0/2）：缺少腕点时已锁定手连续跨肩中线，独立非控制手侧别歧义导致全局清空。修改后两项通过；完整连续性专项包含16项，覆盖异步腕点、人体平移/尺度、副手、交叉、多人、遮挡与不同帧率。由此确认这两条代码路径存在问题，但不能反推用户那次实机的每一段失锁均由它们造成。

锁定后匹配有界的已确认轨迹，同时用当前人体中心/肩宽运输轨迹。只确认当前新鲜检测，不预测有效光标。距离、时间边界不扩大；明确对侧腕更近时拒绝接管，重复/交叉/多人竞争仍暂停。独立副手拒绝仅在轨迹明确分离时隔离。200ms暂停、650ms释放、250ms恢复保留。

原短时驻留保留不符合本次要求，改为任何无效或不稳定观测清零。250ms新鲜稳定移开全部按钮的动作释放锁不变。横向标定收窄至`.28–.72`，实际按钮和预览保持，降低中心到侧目标的输入位移；不声称已证实真人舒适度。
