# V3.5 建筑连续导览验收

验收日期 2026-11-09。开发基线为从远程功能分支获取的 `07bc1c76d990a62e52233f0c3681fd113f900811`。浏览器使用 Windows Chrome 无头模式、实际 WebGL 场景与 4173 正式入口。模块 B 使用同一工作区的 3000 服务。

## 操作与状态

- 建筑总览收到一次向下滚轮或向下方向键后，运行一次既有 `h.go('corridor-2_5d')`。`moveTo()` 用 `travelMs()` 和 `sampleGallery()` 连续采样原轨迹，依次经过建筑总览、接近大门、大门近景、穿过门洞、门内停靠、戏台右侧、右侧廊道、廊道行进、右廊停靠。
- 到达廊道终点后，`wallOnly` 保留墙面转向、标题和亮度渐变，将第一铺定格在 `B / mural-look`。下一次主动操作展开全幅。逐停点按钮、显影重播、返回和后续五铺路线沿用既有交互。
- 镜头和显影共用页面忙碌锁。完成后清空累计滚轮量，设置 400 ms 冷却，冷却期间的滚动每次将安静间隔延续至少 180 ms。按住向下键的重复事件被过滤。减少动态沿用原短转场和标题停留。

- [专项数据](results.json)记录六种视口与动态组合、墙面终态、镜头帧间隔、输入压力、故障注入和正式入口交接。六组均执行单次真实滚轮、墙面停靠、主动全幅、五铺正向与逆向，覆盖原图比例、细读缩放、拖动、方向键、全图索引和碰撞检查。逐项检查页面异常、控制台错误、失败请求和 HTTP 错误。
- 实际录像抽帧核对大门接近、穿门、右廊和第一铺标题显影。自动导览停靠时，相机与既有墙面机位一致，显影亮度达到 1，阅读进度为 0。1440 × 900 普通模式还覆盖按住向下键、连续滚轮、残余惯性、章节与按钮锁定、向上返回、逐停点与重播。
- 模拟一次镜头采样异常，页面显示错误，状态、进度和镜头退回建筑总览，随后一次滚轮重试成功。正式入口覆盖 A01 → A03 → 展厅、第五铺主动进入模块 B、浏览器返回与冷恢复，并验证 B 连接拒绝时留在第五铺。
- 构建检查和 18 项镜头、显影、控制器专项单测通过。较广的 90 项单测中有 88 项通过，两项失败可在基线复现其条件。`ambience.test.mjs` 仍对照更新前的壁画数据快照，`study.test.mjs` 所需的旧路径“第三铺壁画原图.jpg”在基线缺失。这两项测试及其素材保留原样。

普通模式的帧间隔取自镜头轨迹的 `requestAnimationFrame` 回调。它反映测试环境中的采样节奏，实际画面刷新率还取决于浏览器合成及设备。最长间隔见结果表，镜头运动存在偶发卡顿。触控板尾流由测试模拟，现场机位与实体触控板手感仍待实机核对。
