# B03 V4.2 根因诊断

实施基线是本地 HEAD 与 `git ls-remote origin refs/heads/master` 同时确认的 `7a0e2947269529854787edcb0d0fd25f82be9562`。审查了最近两次提交 V4/V4.1 和完整生产链。既有素材新增/删除、归档机制编辑和历史未跟踪截图保留，未纳入本次修改。

## 基线已确认的问题

| 问题 | 代码证据与影响 | 修复 |
|---|---|---|
| 获取与按钮命中耦合 | HandOwnership 未锁时只允许 hitTarget/controlRegions 请求；GesturePointer 只显示正式手。观众在按钮外没有获取反馈 | 在现有 gestureZone 内、归属明确的单手先做连续获取；候选显示但 valid=false；动作仍需正式硬锁、稳定指针和独立1000ms驻留 |
| Hands 与 Pose 时效耦合 | handleGestureLogic 用同一220ms阈值检查 Hands 采集年龄；Hands过期时同时把 Pose.at 替成-Infinity并清空Hands输入。诊断的handsDetected实际是筛选后数量 | Hands独立160ms上限；原始、新鲜、归属数量分别记录；Pose按自身采集时间与有界测量预算判定 |
| 固定Pose时效会在部分负载下拒绝有效观测 | 220ms是采集年龄，包含推理与结果间隔。基线实测空白双模型约Hands30.27/Pose9.69 FPS，采样3.92%过期，首段推理最大约366.9ms | 保持220ms起始值；足够样本后使用采集至返回P95+结果间隔P95+35ms，绝对上限360ms；单个大尖峰不扩成长期有效旧数据 |
| 普通短间断清零 | DwellController任何无效帧都cancel；V4.1恢复还统一要求250ms重新确认，100ms间断也不能保留合法进度 | 同人物同手、安全原因短暂停顿最多200ms；暂停和恢复稳定确认期间不加时间；歧义、跳点、身份改变、明确移出、转场立即取消 |
| 权限等待被统一限时 | Camera.start涵盖权限弹窗和视频启动，15s定时器不区分用户未响应 | 原生权限等待不设模型超时；视频流成立/Camera.start完成后才启动视频无帧判断；退出后的迟到结果清理；下一次启动等待旧请求结算 |
| 会话与异常资源缺少完整屏障 | 单个可复用Hands模型、全局handsFrameVersion/InFlight；退出没有close Hands。Pose submit错误留下error但ready仍可能为真，initialize会提前返回；dispose也没有及时结算初始化Promise | 每个有效会话一个Hands实例，关闭结算后才能新建；回调绑定模型/会话，send与onResults均完成才复用采集画布；异常Pose终止并重新初始化；初始化拒绝与定时器由本Worker管理 |
| 错误来源被掩盖 | 推理/画面转换故障都显示网络初始化失败；普通退出、运行错误、下载与权限无法准确区分 | 明确错误code/source、阶段状态、可见重试与诊断导出；资源下载仍沿用原版本，未顺手本地化模型 |

## 不能据此确认的现场判断

239ms > 220ms 可以解释截图那一个采样点的 POSE_STALE，不能证明每帧都过期。Hands回调30 FPS也不等于识别到了手；旧界面的0只手可能是原始0，也可能已被安全筛选。没有现场视频/逐帧诊断，不能确认用户所有连接失败都来自CDN、设备占用或模型故障，更不能保证本修改已达到真人稳定成功率。

本轮真实模型复测一次Hands初始化15s超时，后续多次模型启动/推理/退出/重入通过。该失败保留为FAIL记录，没有证据证明CDN是用户现场主要原因；没有移除超时或改模型版本来抹除它。完整本地化需要独立版本、WASM、权重、许可/NOTICE与兼容测试，可单列V4.3。

## 实施中发现并修复的回归／测试问题

- 新生命周期最初用 error.code 分类原生DOMException，NotFoundError.code为数字8，导致分类错误；现在只接受字符串自定义code，原生异常用name，真实页面测试和DOMException单元回归通过。这是本轮开发中的回归，不冒充基线已有问题。
- 新watchdog最初使用重入时已重置的lastSubmit=-Infinity，健康旧inFlight帧被误判超时。现使用该任务自身job.at；短时重入等待旧结果并拒绝旧session，真的卡死才销毁Worker。浏览器隐藏恢复和专门单元回归通过。
- 全页十轮脚本在重素材切换后观察到控制手安全释放，旧脚本要求它始终不释放而失败。保留失败帧和轨迹；正式检查现在明确记录afterLoad与recovery，断言释放锁仍在、同侧新鲜获取、不发生重复NEXT/自动开档。没有延长650ms宽限，也不宣称全程无失联。
- B01旧脚本将提示区全部button当成一个按钮；新增明确重试后出现严格选择器歧义。现按“返回选择”名称定位，并等待真实Camera.start阶段后再测试模式退出，保留六次启动/停止、最大一个会话的断言。
- 低帧率测试曾将长时间Pose失效后的安全收起阅读误当成CLOSE手势；现同时断言lastAction仍为OPEN、没有NEXT、手锁已释放，区分页面安全收起与有效手势动作。

这些早期失败、最终结果和可复现限制一并记录，不能用最终PASS覆盖旧FAIL。真人摄像头、多人交叠、距离、光照和长期误触仍为PENDING。
