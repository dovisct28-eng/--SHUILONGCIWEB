## 启动与记录

1. 在仓库根目录执行 `node .\docs\validation\b03-gesture-v4.2\start-physical-acceptance.cjs`。脚本优先复用当前 V4.2 本地服务；端口被旧服务占用时提示手动重启，不终止其他进程。它打开 Chrome 调试页，并在 `local/physical/` 创建全 PENDING 记录。`--no-open` 可只准备记录；旧服务占用3000时，可用 `--port=3002` 在空闲端口启动本项目服务，不终止旧进程。
2. 冷启动前退出当前体感。确需测试无缓存启动时，通过 Chrome DevTools 勾选 Disable cache，并在每轮重载前保持 DevTools 开启。分别记录缓存冷/热，不清理正式素材。权限“询问”和“已允许”分别测试；不要把等待用户点击允许计入模型故障。
3. 记录电脑型号、CPU/GPU、Windows、Chrome、摄像头名称、分辨率、距离、光照、网络和 commit SHA。软件有未提交 B03 改动时记录 `workingTreeChanged=true`，不能用旧 SHA 代表这些编辑。脚本不会自行拍摄、上传视频或关键点。
4. 页面进入体感后，先让双肩进入中央区，再只举一只手进入既有手势范围。应在按钮外先看到浅色候选光标，稳定 350ms 后获得正式光标。稳定指针移到按钮，约 1000ms 有效驻留后触发。不要同时用两只手争夺初始控制权。
5. 每个阶段点击「导出识别诊断 JSON」，将浏览器下载的 JSON 放入 `local/physical/`；填写脚本创建的记录。失败时保留失败与恢复前后两份，附阻断原因，不删失败尝试。导出含状态、错误、指标和临时控制 ID，不含视频、图像或人体关键点。
6. 最后再用普通入口 `http://localhost:3000/index.html` 检查提示、预览尺寸、操作按钮与单光标；调试导出按钮及技术文字应隐藏。

## 故障复现

- 权限拒绝：Chrome 站点设置阻止摄像头，重载进入；应显示权限提示。恢复“允许”后可重试。
- 占用／设备缺失：只在设备允许时用其他摄像头程序占用，或拔出外置摄像头；应区分不可读取、未找到和连接中断。恢复后重试。
- 资源断网：DevTools Request blocking 阻断一个实际 Hands/Pose 资源；应显示资源/模型来源，而非误报权限。解除阻断后重试；所有下载仍依赖原 CDN，本次未实现离线模型。
- 权限迟到：站点设为询问，未点击允许前返回选择，随后允许；旧流必须关闭。期间再次进入再退出也不能在后台重新启动。
- 隐藏恢复：动作后切走 Chrome 标签再返回；新鲜人物、手和指针重新确认，动作释放锁不能凭失联被解除。
- Worker 真实运行错误若无法可控复现，填 NOT_TESTED；不得依据合成故障注入填真人 PASS。

只有目标设备逐轮记录完整且没有未解释失败，才能填写总体 PASS。有失败填写 FAIL；未执行维持 PENDING，确实无法执行的项目写 NOT_TESTED 并注明原因。诊断 JSON 和现场动作记录应同时保留，FPS 较高不能单独证明交互成功。
