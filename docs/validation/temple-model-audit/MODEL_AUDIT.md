## 5. 优先级与下一阶段范围

| 级别 | 建议 | 依据与取舍 |
| --- | --- | --- |
| P0 | **本轮无已证实必须调整项。** 不因此制造模型重构任务 | 五墙归属成立；当前入门/右廊/第一幅镜头采样未碰撞。这个结论不覆盖尚未实现的②路线 |
| P1 · 首选 | 戏台局部体量与台口/后部空间关系做参数候选 | 图6与修复后室内照片均支持当前戏台过度简化；先比较几组局部候选，保留当前台口朝向，逐一复验门内转向与右廊通行，再决定改多少 |
| P1 · 次选 | 主殿山墙与屋顶轮廓局部修正；柱列先做占位验证 | 图纸及修复后右侧照支持山墙差异。优先保持下部两侧壁画面坐标，避免屋面修正变成整殿缩放。内部柱网的修复后依据不足，未证实前不直接落成完整柱网 |
| P1 · 后续接入时 | ③④占位的非等宽边界复核 | 图6与模型有明确差异，但不影响本轮核心壁画体验，不列入下一阶段必改清单 |
| P2 · 保持 | 总体轴线/长条布局、完整两廊、入口通口、①②⑤锚点和图像比例；瓦片、砖纹、小饰件及非关键构件细尺寸 | 核心关系合理，细部精度对本项目收益有限。保留通口和锚点还可减小交互回归范围 |

**推荐下一阶段仅做“戏台体量候选＋主殿屋面/山墙轮廓候选”**；必要时增加主殿柱位的临时遮挡测试。不要先整体缩放，不重做全部动画，不开展精密木构复原。柱列正式落成和③④边界调整可后置。本报告不是对任何候选参数的实施批准；本轮止于审查。

## 6. 生成复用与交互风险

实际链路是：`model-source.js → build-model.mjs → GLB + 独立预览内嵌GLB/模块 + model-info.json + A01线稿数据`。构建器还执行`build-a01-lines.mjs`，**并不自动重写`mural-locations.json`**，而是将源程序壁画数组与该JSON比对，不一致就失败。正式A01–A04复用独立预览的同一运行场景；V2.4-A.1借`gallery-entry`接入该场景，而不是另造模型。旧V1的独立读取器仍保留，但不是当前运行主链。

| 若下一阶段修改 | 需要同步复核的具体依赖 |
| --- | --- |
| 戏台局部扩大/移位 | 源程序重建GLB；`entry-path.mjs`门内机位(0.12,1.38,11.15)、`corridor-path.mjs`绕台段、原台后遮挡与G01场景中戏台轮廓。不能只凭静态顶视图认定通行 |
| 入口/围墙变化 | `temple-runtime.mjs`按固定范围筛除中央门扇的320个三角形；该筛选依赖X±0.761、Y≤1.681、Z约11.70…12.17。还需复验门洞有效高度、近裁面和穿门轨道；门扇只在运行时打开，原GLB未改 |
| 廊宽/右墙/柱列变化 | 右廊轨道X约3.42…3.85；第一幅发现点(3.55,1.38,7.65)，正视点(3.30,1.55,4.8)。柱移位可能挡镜头或壁画；右廊地面目前Y=0.32，投影几何筛选使用0.30<Y<0.33、右墙X>4.4及朝内法线，改变高度/轴线就需重查 |
| ①锚点变化 | 同步源程序、`mural-locations.json`、`FIRST_MURAL`、`v24-murals.mjs`；重算`mural-anchor.mjs`四角、`mural-front.mjs`法线/1.565停靠距离和阅读构图。正视停靠采用3D近看局部，完整图归数字阅读，不能为了容纳全图把相机随意移进庭院 |
| 主殿或屋顶变化 | A01总览构图/线稿、A02五墙标记、A03剖切与遮字、A04路线及屋面移动窗口都需回归。`a04-scene.mjs:17`仍有基座范围常量；扩大总包络也会影响自动取景。屋顶局部修改通常不要求重写入门轨道，但改变光影仍需看实际画面 |
| AI场景复用 | 当前`v24a-layer.mjs`读取`assets/v24a/references/camera-manifest.json`的三组相机矩阵，使用G01/G02/G03投影到原右墙/廊地面，并依机位混合。它们不是仅靠壁画锚点定位的整屏背景；墙、地、柱、戏台或参考机位变动后，要重导参考帧/矩阵并核对取样边界、深度遮挡，必要时才考虑局部替换生成资产 |

正视转向的后半段，`v24aFrontConfidence`主动衰减场景投影；本轮正视终点墙/地投影增益都为0，所以第一幅近看仍依赖原模型和独立真实图。这不等于既有AI图适配任意新结构。旧S01–S04只是保留的V1资产，不代表V2.4-A.1当前所用三组投影。

**未来②路线：** 右廊可以在空间上继续向主殿推进，主殿前沿右柱(3.6,−8.35)应列为绕行/转入核查点。`v24-murals.mjs`的②停靠仍标`candidate-not-implemented`；合理可达是规划判断，本轮没有实现或验收该路线。保留坐标也不能免除未来通行测试。

## 7. 验证与未解决信息

- 原GLB正交顶视/正视/侧视/鸟瞰共4张，沿用GLB内嵌材质纹理，使用独立中性检查灯光；没有网页UI、环境装饰或AI图。顶视只在检查场景隐藏roof材质网格以显示布局，完整屋面顶视留本地；原GLB与正式材质文件未变。
- SVG含独立轮廓、线、柱点、标签与尺寸，无嵌入位图；两图各自等比且主体纵长归一，不能作为同一米制比例尺。已检查1800×1320预览的文字和标注。
- 模型/源等价/展厅逻辑相关测试 **38/38通过**。实际Chrome 1440×900下，V2.4-A.1总览→穿门→绕台→右廊→①发现→数字阅读→反向返回，共15个状态检查通过，页面/资源错误为0。
- 原运行模型的300段轨道、中心与±0.065设计单位轴向偏移、双向共4200条射线，当前相机包络碰撞为0；包含穿门/右廊2800条和①正视过渡1400条。是离散的相机包络检查，不是连续体碰撞求解、真人可达性、实体相机或现场测量。
- 最终文件检查对开工时所有已跟踪文件逐一比较SHA-256及删除状态，保留既有未提交工作；归档Tag仍固定。未新增正式页面代码，无打包器构建任务；检查脚本语法、静态资源实际加载及既有模型测试代替构建验收。详见[精选/复验记录](README.md)、[文件保护结果](file-checks.json)。

仍缺：统一边界的修复后测绘、主殿完整现状柱网、③④现状精确边界、②的正式通行路线。它们不妨碍保留主体与提出局部候选，但不能被本轮静态对照或测试结果替代。
