实施基线：`485e26baef3140df298d64cd9779083079bd9847`。2026-10-08 开始时本地 HEAD 与 GitHub master 一致。本次只改 B03 控制权、必要驻留兼容、反馈及相关测试；模块 A、B01/B02 生产逻辑、人物素材、构图、材质和摄像头预览保持。

## 已实现机制

人物仍由 OperatorTracker 获取与归属；新增唯一的 HandOwnership 状态源，使用其语义 `operatorId:side` 锁定控制手。保留 `maxNumHands:4`、原 Hands/Pose 检测与所有骨架绘制。只过滤最终交互输入，不隐藏第二只手假装独占。

尚未锁手时，仅一只归属于当前观众的新鲜手进入当前可用按钮或实际阅读控制区，连续 350ms 才获得控制权。双手同时请求时清空候选并等待。获取不触发动作；指针重新稳定后，按钮从零开始现有 1000ms 驻留。

锁手后仅该身份生成有效指针；另一只手的位置、顺序和目标请求只记为 ignored。控制手短暂丢失或人体/手部归属歧义立即停止输入并取消驻留，保留身份至最后有效观测后 650ms；其他手不能接替。恢复需连续 250ms 新鲜观测，重新建立指针平滑/稳定证据。超过 650ms 释放，重获必须再完成候选获取。原 200ms 追踪暂停窗口用于指针淡出与观测连续性，不能把旧坐标补算为驻留时间。

OPEN、CLOSE、NEXT 和资源/动画锁保留同一手。动作后 `releaseRequired` 仍要求当前控制手在所有可用动作目标外稳定 250ms；失联、换手和重新获取都不能自动绕过。退出、摄像头停止、隐藏/卸载、人物正式释放清除手锁与指针；手锁不延长原人物 1000ms 丢失宽限。

## 初始参数与边界

| 参数 | 初始值 | 用途 |
|---|---:|---|
| controlHandAcquireMs | 350ms | 独立控制手获取 |
| controlHandLossGraceMs | 650ms | 暂时失联保留身份 |
| controlHandRearmMs | 250ms | 恢复后的新鲜观测确认 |

以上是实机标定前的起始值，不是现场验证结果。按钮 1000ms、释放 250ms、人物获取 800ms、人物释放 1000ms，以及现有指针映射/滤波参数保持。OperatorTracker 已镜像 palm x，本层不再镜像，也不按屏幕左右推断手侧。

## 真实设备限制与失败记录

Chrome 实际渲染 Three.js/GSAP 和原页面；控制权/驻留验收的摄像头像素、Hands 与 Pose 输出是合成数据。真实模型运行检查使用空白合成 320×240 图像，只验证模型启动/运行/退出，不能证明真人手侧稳定、重叠、遮挡或成功率。

首轮驻留浏览器脚本在 NEXT 进度约 0.92 时就检查索引；动作等待从 1450ms 改为 1800ms，以覆盖既有指针大跳变稳定窗口与完整驻留，生产阈值未放宽。首轮控制权专项合成单手 Pose 把缺失右腕放在左手附近，触发正确的 AMBIGUOUS_SIDE 安全拒绝；修正 fixture 的缺失右腕可见性后重测。后续加强连续手锁断言的检查在第八轮出现释放等待超时：控制手已释放，中性区不能获得新的手锁。现记录每次释放的有效观测间隔与上下文，并让验收辅助函数在手锁依法失效后重新进入目标获取、再完成释放；不放宽650ms阈值，不清除既有releaseRequired。最终报告分别保留十轮动作、前后手键与释放轨迹，不能把安全重获说成从未失联。原始失败 JSON/截图留在 local，失败摘要及代表帧提交，不隐去失败。

最终加强检查完成十轮，同一语义手侧未被另一只手接管；但第七次NEXT切换后记录到656.1ms有效手观测空窗，按650ms规则安全释放，随后重新完成获取与释放约束。不能把该结果写成十轮完全不失联或始终保持同一次手锁。是否由素材切换负载/推理时序引起尚未确认，需要现场检查与参数标定；本次不改素材、加载或舞台算法。真实摄像头十项均为 PENDING。语义手侧依赖现有 OperatorTracker/Pose 的可靠输出；多人交叠、低光、真实 Hands/Pose 延迟和机器负载仍需现场检查。严重归属歧义可暂停甚至释放手锁，这是安全判断。外部资源依赖和旧阶段冷启动风险没有由本任务解决。既有未提交素材/删除、归档改动和历史截图不纳入本次提交。
