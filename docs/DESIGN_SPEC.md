# 设计规格（DESIGN_SPEC）

> 本文件只描述实际的网页设计和交互逻辑，不描述研究背景与具体代码实现。项目背景见 PROJECT_CONTEXT.md。

## 模块 A：水龙祠壁画叙事引导页面

滚动驱动的空间与叙事变化：通过滚动控制镜头移动、空间缩放、建筑平面变化、壁画横向移动、信息出现/隐藏、视觉焦点变化。

### A01 开屏

- **目标**：建立水龙祠的空间认知。
- **内容**：水龙祠建筑/建筑平面；平面生长或空间生成动画；简短介绍；向下探索提示。
- **约束**：文字必须克制，不要做成历史资料首页。

### A02 建筑空间

- 通过 Scroll 呈现：水龙祠整体 → 建筑布局 → 壁画位置。
- **目标**：让用户知道“壁画在哪里”。
- **空间基准**：以用户提供的布局示意图和站位说明为准。观众站在主殿、面向戏台时，身体右侧为第五幅；前行并左转到第一幅；继续前行到主殿右侧的第二幅。示意图见 `CONTENT_MAP.md`，不作为建筑测绘或历史观看路线证据。

### A03 出兵·入将

- 建立五铺壁画之间的空间关系；核心观看路径涉及第五幅、第一幅、第二幅，不等于五幅依编号顺序观看。
- **核心主题**：出兵·入将。
- **约束**：具体内容必须以可靠资料为准。

### A04 观看秩序

- **重点表现**：观众站在主殿、面向戏台时，从身体右侧的第五幅出发，前行、左转到第一幅，再前行到主殿右侧的第二幅，即第五幅 → 第一幅 → 第二幅。
- **交互方式**：向下滚动推进数字叙事；镜头应表达前行和转向，可在局部使用横向画面运动，但不能将整条路线简化为始终向左平移。
- **注意**：“右→左”是项目空间路线的简写，不是三幅壁画在同一墙面上的排列，也不是已经证实的历史观看顺序。交互操作方向与空间路线须区分。

### A05 壁画介绍

- **信息层级**：整体 → 局部 → 细节。
- **建议**：短标题；一段极短说明；点击/滚动后显示补充信息。
- **约束**：避免大量文字。

### A06 聚焦《入将图》

- 通过缩放、镜头推进、视觉弱化、空间聚焦，将用户注意力集中到《入将图》。
- **最终显示**：“进入探索”入口（进入模块 B）。

## 模块 B：《入将图》交互探索（Mural-Exhibition）

### 核心原则

- 模块 B 的核心交互已基本完成，后续工作首先应保护现有功能，而不是重新设计。
- 模块 A 只负责提供进入模块 B 的入口。
- 模块 B 自身保持独立开发和维护。
- 模块 B 的具体交互内容以当前项目代码为准，本文件不重新定义。

### 现有入口与数据（以当前代码为准）

- 大屏展厅版（WebGL）：`http://localhost:3000/`（`Mural-Exhibition/public/index.html`）——模块 A“进入探索”的目标入口
- 移动端叙事长卷版：`http://localhost:3000/m`（`Mural-Exhibition/public/gallery.html`，归属模块 B，当前不接入模块 A）
- 数据接口：`/api/scan-assets`（动态扫描 `Mural-Exhibition/public/assets/` 下的壁画系列，返回各系列 org/line/color/info 素材路径）

### 模块 A → 模块 B 连接方式

- 通过明确的入口或路由完成，不做内部耦合；
- 模块 A 的“进入探索”按钮跳转到**大屏展厅版（WebGL）** `http://localhost:3000/`；
- 移动端叙事长卷版（`/m`）当前不接入模块 A（忽略）；
- 不直接修改模块 B 的缩放逻辑、热点系统、Canvas/WebGL 核心、大图加载逻辑、节点系统。
