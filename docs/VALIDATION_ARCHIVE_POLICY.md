# 验收截图精选留档规范

2026-10-06 起适用于模块 A、模块 B、shared 的后续所有阶段。此规则控制提交到 GitHub 的截图范围，不减少测试覆盖，也不追溯整理或删除已存在的历史证据。

## 后续阶段的目录约定

```text
docs/validation/<阶段>/
  README.md              验收结论、精选清单、验证范围与限制
  selected/              必要关键帧和代表性交互状态，提交 GitHub
  local/                 完整回归、重复状态、临时或排查截图，仅保留本地
```

现有阶段沿用原路径，无须搬迁。后续脚本默认把整批截图写入 `local/`，验收完成后只将必要截图复制到 `selected/`；原始捕获保留。测试结果、失败记录和说明应如实保留，不因截图筛选而隐去问题。

## 如何精选

- 选择能够证明本次改动的必要关键帧，以及代表性的进入、展开、收拢、切换、阅读等交互状态；仅保留与本次任务有关的状态。
- 按任务要求完成全部视口和功能验证，再选择足以说明布局差异、边界状态或修复结果的截图。若任务明确要求特定视口和状态截图，仍须满足该要求。
- 相同状态的反复捕获、没有新增信息的回归截图、运行过程临时图留在 `local/`。重要差异、失败或未解决问题在验收记录中说明，不以精选结果宣称全部通过。
- 精选截图必须来自实际运行。参考图与运行证据分开标注；设备模拟、合成测试素材及未完成的真实设备测试需写明。
- 可使用无损压缩减少上传量，保持原尺寸、可读性和内容一致；保存原始捕获，不修改或覆盖正式素材。展板辅助浏览，不能替代必要的可读截图。

## 提交前检查

在阶段 README 中列出精选文件及其状态、视口、验证结论和限制。检查暂存区文件范围、截图数量、单文件大小及总体积，只提交必要截图和相关记录；不要直接把整个回归输出目录加入暂存区。

`.gitignore` 仅新增忽略后续阶段的 `local/`。它不会自动取消历史已跟踪文件；不得为落实此规则批量执行历史截图的 `git rm --cached` 或改写已发布历史。当前 B03 原始 PNG 的既有本地保留规则继续有效，精选无损 WebP、展板和报告保留在 Git 中。

## 保护边界

正式设计素材、壁画母版、展示资源和历史验收证据均不得删除。不得将正式素材移入 `local/` 规避版本管理；不得运行清理命令删除本地验收目录。新规则只决定后续新增截图是否提交，不授权历史清理、Git 垃圾回收或用户未提交文件的删除。
